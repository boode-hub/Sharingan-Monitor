================================================================================
SHARINGAN SYSTEM TRAY MONITOR - FULL BUILD PROMPT
================================================================================
Hand this file over on its own and the whole project can be rebuilt in one pass.
It contains the goal, the exact spec, the architecture decisions that matter,
and the mistakes that cost time the first time round. Read the "PITFALLS"
section BEFORE writing any code - most of it is non-obvious and every item in
it was discovered the hard way.


--------------------------------------------------------------------------------
1. WHAT IT IS
--------------------------------------------------------------------------------
A single native PowerShell script (p2.ps1) that lives in the Windows system tray
and renders an animated Naruto Sharingan eye as the tray icon. The eye reacts to
live system load:

  - The eye "evolves" through 5 stages as CPU (or RAM) load rises:
        stage 0 = plain eye, no tomoe
        stage 1 = 1 tomoe
        stage 2 = 2 tomoe
        stage 3 = 3 tomoe
        stage 4 = Mangekyou (the character's unique pattern)
  - The eye spins continuously, faster under higher load.
  - Right-clicking the tray icon opens a menu to swap CPU/RAM tracking, pick an
    eye, customise behaviour, and exit.

No external dependencies, no compiled binaries, no installers. Pure PowerShell +
System.Drawing (GDI+) + System.Windows.Forms.


--------------------------------------------------------------------------------
2. FILES TO PRODUCE
--------------------------------------------------------------------------------
  p2.ps1                the entire application
  install-startup.bat   enable at login + launch now
  remove-startup.bat    remove from login + stop the running instance
  settings.json         created at runtime, not shipped
  sharingan.pid         created at runtime, not shipped

An older prototype (p1.ps1) once lived here and was the source of Sasuke's
Mangekyou artwork. It has since been deleted - section 5 below describes that
artwork in full, so nothing depends on it.


--------------------------------------------------------------------------------
3. SCRIPT STRUCTURE (p2.ps1)
--------------------------------------------------------------------------------
Keep these numbered sections, in this order. It makes the file navigable.

  1.  Win32 interop      - Add-Type C# class exposing GetCPULoad / GetRAMLoad /
                           DestroyIcon.
  2.  Global state       - runtime state + user settings + factory defaults.
  2b. Settings           - Save-Settings / Load-Settings / Reset-Defaults.
  3.  Tray icon + menu   - NotifyIcon, ContextMenuStrip, eye list, Set-EyeStyle.
  3b. Customize submenu  - all user settings, built as menu items.
  4.  Fill-CurvedBlade   - drawing helper.
  5.  Get-SharinganIcon  - the whole renderer.
  6.  Animation          - WinForms Timer + Application::Run.
  7.  Exit cleanup.

METRICS (section 1) - use a C# class via Add-Type:
  - CPU: System.Diagnostics.PerformanceCounter("Processor","% Processor Time",
    "_Total"). This matches Task Manager. Prime it with one throwaway NextValue()
    in the static constructor, and sleep ~200ms before the first real read.
  - RAM: GlobalMemoryStatusEx via P/Invoke, return dwMemoryLoad.
  - DestroyIcon from user32.dll - REQUIRED, see PITFALLS.


--------------------------------------------------------------------------------
4. THE RENDERER  (Get-SharinganIcon $E $Angle $Style)
--------------------------------------------------------------------------------
  - Draws onto a 128x128 Bitmap, then GetHicon() -> Icon::FromHandle. Windows
    scales it down to 16x16 in the tray, so 128 gives clean anti-aliasing.
  - $E is a FLOAT from 0.0 to 4.0 - the morph stage. Everything scales smoothly
    off the fractional part so stages blend rather than snap.
  - $Angle is the rotation in radians.
  - SmoothingMode = AntiAlias, PixelOffsetMode = HighQuality.
  - Return BOTH the Icon and the raw handle:
        [PSCustomObject]@{ Icon = $icon; Handle = $hIcon }
    The caller must DestroyIcon the handle every frame.

Draw order:
  A0. Glow (colour only - see section 6)
  A.  Sclera: filled circle at 6,6,116,116 in the eye colour, black 4.5px border
  B.  Inner ring: fades in over stages 0->1, solid 1->3, fades out 3->4
  C.  Centre pupil: radius 14.0, some styles adjust it at stage >= 3
  D.  Mangekyou pattern: only when $E >= 3.0, scaled by ($E - 3.0)
  E.  Tomoe: three of them, each with its own fade-in window and a curved tail

Fill-CurvedBlade $g $brush $baseAngle $startRadius $length $scale $curveFactor
$maxWidth - draws a tapering curved blade as a run of ~30 overlapping circles.
Crude, but it anti-aliases beautifully and is how most Mangekyou styles are
built.

EYE LIST - exactly these 18, in this order. Sharingan only. Do NOT add Rinnegan
or Byakugan; they were removed deliberately because they are not Sharingan.

  Itachi, Obito, Kakashi, Madara, Izuna, Sasuke, Shisui, Indra, Shin, Sarada,
  Naka, Baru, Rai, Naori, Fugaku, Nanashi, Madara Eye 2, Sasuke Eye 2

Define this list ONCE as $global:SharinganStyles and build the menu by looping
over it. The shuffle pool and the check marks must read from the same array, or
they drift apart.


--------------------------------------------------------------------------------
5. SASUKE'S MANGEKYOU  (specific requirement)
--------------------------------------------------------------------------------
The "Sasuke" style (NOT "Sasuke Eye 2") uses a six-pointed star, built like this:

  - Translate to centre, then for i in 0..2:
      rotate by (Angle in degrees) + (i * 60)
      fill a black ellipse, semiMinor 13.0*mScale wide, semiMajor 50.0*mScale tall
      fill an inner cutout in the EYE COLOUR, 3.5 / 4.5 smaller on each axis,
        with alpha = mScale*255 so it fades in with the morph
  - Then a black centre pupil, radius 9.0 * mScale.
  - The pupil branch in section C shrinks for Sasuke: 14.0 - (7.0 * mScale).

The inner cutout MUST use the current (possibly glow-brightened) eye colour, not
a hardcoded red - otherwise picking blue gives a blue eye with red cutouts.

"Sasuke Eye 2" is a different design (3 ellipses at 120 degrees plus crosshair
lines) and stays exactly as it is.


--------------------------------------------------------------------------------
6. USER SETTINGS
--------------------------------------------------------------------------------
All of these live in the tray menu (see section 7), persist to settings.json,
and apply live without a restart.

  THRESHOLDS   Four load percentages that unlock stages 1..4.
               Default 15 / 35 / 55 / 75.
               Offer 0,5,10,...,95 per stage.
               MUST stay strictly ascending. Clamp the picked value so every
               stage keeps a 5% gap:
                   lo = index * 5
                   hi = 100 - (3 - index) * 5
               then push neighbours out of the way in both directions. Without
               the clamp, dragging the top stage down collapses the lower ones
               onto each other and a stage becomes unreachable.

  COLOUR       Replaces the default red (220,10,15) everywhere the eye colour
               appears - the sclera and Sasuke's star cutout. Everything else
               stays black. Offer ~10 presets plus a ColorDialog picker, and
               show the current colour as a disabled "Current: <name>" item.

  SPEED        Multiplier on the rotation rate. Default 1.0x.
               Offer 0.20x 0.40x 0.60x 0.80x 1.00x 1.25x 1.50x 2.00x 2.50x 3.00x.

  SHUFFLE      Off by default. When on, switch to a random DIFFERENT eye every N
               seconds. Offer 5s / 10s / 30s / 1min / 5min / 15min, default 10s.
               Reuse the existing frame counter, do not add another timer.

  GLOW         Off by default. CRITICAL: glow must NOT change the eye's size,
               position or animation in any way. It is a COLOUR change only -
               the eye should look lit from within, brighter, popping out.
               Implementation: push the colour to full saturation
               (multiply all channels by 255/max_channel), then lift 28% toward
               white. Optionally add a very faint bloom into the unused 6px
               canvas margin - that costs no eye size because the sclera still
               draws at 6,6,116,116.
               An earlier attempt scaled the whole eye down to 0.84 to make room
               for a halo. That was wrong and was rejected. Do not do it.

  RESET        Restores: thresholds 15/35/55/75, colour red (220,10,15),
               speed 1.0x, glow off, shuffle off, interval 10s, eye = Itachi.
               Must also re-sync every check mark in the menu.

PERSISTENCE - settings.json next to the script, via ConvertTo-Json /
ConvertFrom-Json. Store the colour as separate R/G/B ints. Wrap both save and
load in try/catch: a read-only folder or a corrupt file must never take the tray
icon down. Save on every change and once more on exit.

EVERYTHING IS IN THE MENU. Do not build a settings Form - see PITFALLS, this is
the single most important decision in the project.

Write one helper that turns a menu item into a radio-style list of choices with
the current value check-marked, and one Sync function that re-ticks every check
mark from current state. Call Sync after any change. One source of truth.


--------------------------------------------------------------------------------
8. ANIMATION LOOP
--------------------------------------------------------------------------------
Use a System.Windows.Forms.Timer (Interval 35ms, ~28fps) whose Tick renders one
frame, and drive the process with [System.Windows.Forms.Application]::Run().

Per frame:
  - Every 1000ms, re-sample CPU or RAM.
  - If shuffle is on, count up and swap eye when the interval elapses.
  - Map load to a target stage using the four thresholds.
  - Ease the current stage toward the target: current += (target-current) * 0.12
  - speedFactor = 0.01, or 0.02 + (load/100)*0.26 once past threshold[0];
    then multiply by the user speed multiplier.
  - Advance rotationAngle, wrap at 2*PI.
  - Build the icon, assign it, dispose the previous Icon, DestroyIcon the handle.
  - Update the tooltip: "Sharingan (<Style> <CPU|RAM>): <load>%"

Exit menu item calls Application::ExitThread(). Cleanup then saves settings,
deletes the pid file, hides and disposes the NotifyIcon.

Any variable the Tick scriptblock ASSIGNS to must be $script: or $global: scoped.
A plain $var assignment inside the scriptblock silently creates a local copy and
the counter never advances.


--------------------------------------------------------------------------------
9. BATCH FILES
--------------------------------------------------------------------------------
install-startup.bat
  - Generate a 2-line launcher.vbs that runs PowerShell fully hidden:
        Set s = CreateObject("WScript.Shell")
        s.Run "powershell.exe -NoProfile -ExecutionPolicy Bypass -File ""<script>""", 0, False
  - Add HKCU\Software\Microsoft\Windows\CurrentVersion\Run -> SharinganMonitor
    pointing at wscript.exe //nologo "<launcher.vbs>"
  - Launch it now, unless sharingan.pid already exists.
  - HKCU means no admin prompt. The VBS shim is needed because
    "powershell -WindowStyle Hidden" still flashes a console window at every boot.

remove-startup.bat
  - Delete the Run value.
  - Read sharingan.pid, and before killing, confirm the PID still belongs to a
    powershell/pwsh process - a stale pid file could otherwise name a process
    Windows has since recycled.
  - Delete launcher.vbs and sharingan.pid. Keep settings.json.

p2.ps1 writes $PID to sharingan.pid on startup so the uninstaller can find it.


--------------------------------------------------------------------------------
10. PITFALLS - READ BEFORE CODING
--------------------------------------------------------------------------------
NO POP-UP SETTINGS WINDOW. This is the big one. A tray app has no main window,
so a Form opened from the tray menu has no owner. Windows then refuses to
activate it while another application holds the foreground, and it appears
behind everything or on whichever monitor was last used. It looks exactly like
the menu item doing nothing at all. Symptoms observed: Visible reported True
while the Win32 IsWindowVisible reported False, window placed at X=2522 on a
secondary display, and the process hanging on exit. Activate(), BringToFront(),
TopMost and manual screen placement all fail to fix it reliably.
Put the settings in the ContextMenuStrip instead - the shell owns that window,
so none of this applies. If a free-typed value is ever genuinely needed, a
ColorDialog-style MODAL ShowDialog does activate correctly; a modeless Form
does not.

DO NOT hand-pump with "while + DoEvents + Start-Sleep". That blocks the UI
thread for most of every tick and starves anything that needs the message pump.
Use a Timer under Application::Run.

ALWAYS DestroyIcon the handle from GetHicon() every single frame, and Dispose
the previous Icon. At 28fps a leak here exhausts GDI handles within minutes.

POWERSHELL SWALLOWS EXCEPTIONS thrown inside WinForms event handlers. A broken
handler is completely silent. Wrap risky handlers in try/catch and surface the
error, or debugging is guesswork.

KEEP THE FILE ASCII WITH CRLF LINE ENDINGS. There is no BOM, so Windows
PowerShell 5.1 reads it as ANSI. Write "Mangekyou", never "Mangekyo" with the
macron - a non-ASCII byte will corrupt.

$this INSIDE add_Click refers to the menu item that was clicked. Use $this.Tag
to carry the item's value; it avoids one closure per item.

A ToolStripMenuItem THAT HAS CHILDREN does not fire Click - it opens its
submenu. Only leaf items can act.

ROUTE ALL STYLE CHANGES through one Set-EyeStyle function that clears every
check mark then ticks the right one. Shuffle, Reset, the menu and the saved file
all need it, and duplicating that logic is how check marks go stale.

DO NOT double-register an event handler. add_Click appends, it does not replace.

EVERY MANGEKYOU PATTERN MUST DO TWO THINGS, and it is easy to forget either:
  1. Reference $Angle, so it spins with the rest of the eye.
  2. Scale every dimension by $mScale, so it grows out of nothing instead of
     appearing at full size the instant the stage is crossed.
Seven of the eighteen styles originally failed one or both - Kakashi, Naka, Baru
and Shin were drawn at fixed coordinates and never moved at all, while Sarada's
ring and Naka's centre were hardcoded sizes that popped in. Test it, do not
eyeball it: hash two frames rendered at different angles and assert they differ,
and compare ink at mScale 0.00 vs 0.04 to catch pop-in.

DO NOT use white anywhere in the renderer. Everything is the eye colour or black.
A stray Brushes::White highlight reads as a cartoon eye-glint and looks wrong.

WATCH FOR Brush PASSED WHERE A Pen IS EXPECTED. $g.DrawEllipse($someBrush, ...)
does not fail - PowerShell silently coerces it through the Pen(Brush)
constructor, building an undisposed Pen on every frame.


--------------------------------------------------------------------------------
11. VERIFY BEFORE REPORTING DONE
--------------------------------------------------------------------------------
Do not claim a fix works without having run it. Specifically:

  - Parse check the file:
        [System.Management.Automation.Language.Parser]::ParseFile(path,
            [ref]$null, [ref]$err)
  - Render every one of the 18 styles at several stages and confirm no
    exceptions.
  - Walk the built menu tree programmatically, PerformClick() the leaf items,
    and assert the globals and check marks actually changed.
  - Assert the threshold clamp keeps all four strictly ascending, including when
    the TOP one is dragged to the bottom.
  - Assert glow leaves the rendered eye's bounding box byte-identical - measure
    it, do not eyeball it - while measurably raising the luminance.
  - Round-trip settings through disk and confirm they come back equal.
  - Launch the real script, confirm it stays alive and Responding, then stop it.
  - Render a contact sheet to PNG and actually LOOK at it. Several bugs here
    were only visible as pictures - the glow being invisible at tray size, and
    the glow shrinking the eye.

Clean up every temp file afterwards.
